01What revision 3 changes

Revisions 1 and 2 were built on the internal Fusion Flow backend spec and the ServiceNow-era TSS API. The transition API is a different product: different host, different auth, different verb model, and a scope that covers every declaration type rather than simplified Route A.

DimensionWas (ServiceNow / rev 2)Now (Transition API)
Hostapi.tradersupportservice.co.uk/apitt.nc-tss.uk/api/v1/trader_api/transition
AuthHTTP Basic, re-sent on every callOAuth2 client credentials → Keycloak realm TSS_Portal, bearer token
VerbsEndpoint per actionOne POST per resource; the action is op_type in the body
Goods per consignment99999
ScopeENS · SFD · SDIENS · SFD · SDI · FFD · IMMI/SPIMM · Maritime Inventory Claim · GMR
Agencyaccount-levelactAs query param on every call + /agent_relationships
Importer eligibilitydiscovered by failure (Rule 13)pre-checkable — GET /permission_grant
Choice listscache with varying column names133 named lists, one shape, ETag on commodity_code
Update semanticspartialfull replace — omitted optional fields are reset to blank
Response enveloperesult dict-or-list{result:{reference,status,process_message}} on POST; {result:{…}} on GET
The full-replace update rule drives the whole storage design. Because an update resets any optional field left out, an amendment cannot be a diff. STG must hold a complete document for every entity, and an amend must be assembled from the replica plus the change, never from the change alone. This is the single most consequential line in the new spec.

Permission grant retires Rule 13 as a guess. The old failure mode — an unregistered importer EORI meaning the SDI silently never generates — is now a pre-flight question with a definitive answer. It belongs in validate, not in production diagnostics: check the EORI before a movement is ever staged, cache the answer, and reject with a reason the operator can act on.
Primeline is the actAs case. PLE is a carrier/agent, so every PLE call carries the importer's customer_account_sys_id. That makes actAs a property of the movement, not of the client — PRS.Declaration.act_as_sys_id and STG.Submission.act_as_sys_id both carry it, and a submission with a stale or missing value is an authorisation failure, not a data failure.

Never hard-code a status string comparison. 13.3 — control_status is a different axis

Present on ConsignmentReadResult, SimplifiedDeclarationReadResult and InternalMarketMovementReadResult, alongside and independent of status. It reports customs control and inspection selection. A declaration can be Authorised and still under control — treat it as a second column, never fold it into the first, and surface it on the operator view because it is the thing that stops a truck.

-- resolve a status; an unmapped value is a finding, never a silent no-match
CREATE VIEW CFG.vw_Status_Resolve AS
SELECT c.client_code, c.movement_key, c.decl_type, c.tss_status,
       COALESCE(m.internal_status,'UNKNOWN') AS internal_status,
       COALESCE(m.is_alertable, 1)        AS is_alertable,
       CASE WHEN m.entity_type IS NULL THEN 1 ELSE 0 END AS is_unmapped
FROM CTL.Declaration_Status c
LEFT JOIN CFG.Status_Map m
  ON m.entity_type = c.decl_type AND m.tss_status = c.tss_status;

#DecisionRecommendation
D1Do we build for the transition API only, or run both surfaces during the private beta?Both, behind CFG.Environments and API.Operation_Catalogue. The beta is H2 2026 and the ServiceNow surface carries live movements until it isn't.
D2Which route goes first on the new API?Route A against the vendor's own end-to-end test — it is a working, asserted sequence and makes an excellent conformance suite.
D3Re-verify R11 transport_charges and R12 arrival_port.Pull the transport_charge and port choice lists on day one of access. Two Belfast codes appear in vendor samples.
D4Where does the permission-grant check sit?In validate, with a cached answer and a TTL. It is the cheapest test in the pipeline and it retires the most expensive silent failure.
D5999 goods — do we still split?Split at the TSS limit only. The old 99 threshold was a constraint, not a preference, and splitting creates transport-document suffixes that complicate reconciliation.
D6Retention for API.Request/Response bodies at ~1,000 calls per large submission.Full bodies for 90 days, then archive to ARC keeping headers, status and error details. Decide before the first 999-item movement.
D7Is actAs a client attribute or a movement attribute?Movement. PLE acts for many importers; storing it on the client forces one relationship per client schema.
D8Who owns the 133-list choice sync?A scheduled job with per-list state in CFG.Choice_List. Conditional GET on commodity_code, full pull on the rest, and a failed list does not fail the run.
D9Do we implement reclassification (H1↔H8) in R1?Model it now, build it in R2. The columns cost nothing; the workflow needs IMMI to be live first.
